Contexto · parte 1

Qué pidió el enunciado

AutoRent Express S.A. necesita una plataforma de renta de vehículos con tres roles: cliente, agente de renta y administrador. La parte difícil no es el catálogo de carros: es el ida y vuelta entre cliente y agente para cerrar una renta, y el precio, que depende del plan contratado.

Esos dos problemas — el ciclo de vida de la reserva y el cálculo de la tarifa — son exactamente los que resuelven los tres patrones de esta presentación.

El flujo del negocio

El recorrido de una renta, y quién actúa en cada paso

Ninguno de los dos puede avanzar solo: se van pasando el turno. Eso es justamente lo que el patrón State vigila.

El paso 3 es el importante: es el único momento en que se calcula dinero, y por eso es donde los tres patrones trabajan juntos.

Cómo se conecta con la aplicación

Del clic del usuario a la clase de estado

Django organiza el código en MTV: plantilla, vista y modelo. Los patrones viven en el modelo, no en la vista. La vista sólo traduce el clic en una llamada de negocio y muestra el error si lo hay.

El código de la vista, completo

Una sola línea de negocio

# reservas/views.py
@login_required
@require_POST
@transaction.atomic
def aceptar_reserva(request, reserva_id):
    if not es_cliente(request.user):
        return HttpResponseForbidden('Solo el cliente puede aceptar.')

    reserva = get_object_or_404(
        Reserva.objects.select_for_update(),        # bloqueo de fila
        pk=reserva_id, cliente__usuario=request.user)

    try:
        reserva.aceptar()                          # ← toda la regla vive aquí
        messages.success(request, 'Reserva aceptada.')
    except ValidationError as error:
        messages.error(request, ' '.join(error.messages))

    return redirect('reservas:detalle', reserva_id=reserva.id_reserva)

Detalle de robustez que conviene mencionar: corre dentro de transaction.atomic y toma la fila con select_for_update(). Si dos peticiones intentaran avanzar la misma reserva al mismo tiempo, la segunda espera — no hay dos transiciones simultáneas, y si el cálculo de precio falla, la reserva no queda a medio camino entre dos estados.

Las ocho vistas de reservas/urls.py siguen el mismo molde: verificar rol, tomar la fila, llamar al método del modelo, traducir el error a un mensaje.
