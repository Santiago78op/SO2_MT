Factory Method

«Define una interfaz para crear un objeto, pero deja que sea la implementación la que decida qué clase concreta instanciar.»

Implementado como PlanRenta.calculo() en reservas/models.py.

Para entenderlo · la analogía de la tubería

Le pedís un nombre a la tubería y ella te da el enemigo

Vos no armás al Goomba pieza por pieza. Sólo decís «GOOMBA» y la tubería sabe cuál construir. Eso es una fábrica: le das un nombre, te devuelve el objeto correcto.

Último pedido: —

Pedile un enemigo a la tubería. Después probá 'DRAGON', que no está en la lista, y mirá qué pasa.

En la tubería

tuberia.crear('KOOPA') → te devuelve un Koopa. Vos no sabés cómo se arma; sólo sabés pedirlo por su nombre.

≡

En AutoRent

plan.calculo() lee 'SEMANAL' y te devuelve un TarifaSemanal. Reserva nunca escribe ese nombre.

Para agregar un enemigo nuevo no se toca a Mario: se agrega a la lista de la tubería. Igual que agregar un plan de renta nuevo al diccionario _PRODUCTOS.

Problema y solución

¿Quién decide cuál Strategy se usa?

Strategy resolvió cómo se calcula. Queda un hueco: el plan que eligió el cliente está guardado en la base como un texto ('SEMANAL'). Alguien tiene que traducir ese texto a un objeto — y si esa traducción la hiciera Reserva, el Context volvería a conocer los nombres de las clases concretas, justo lo que Strategy vino a evitar.

El Creator conoce a los productos; Reserva no. Ese es todo el punto.

El código real

El discriminador persistido fabrica el producto

# reservas/models.py
class PlanRenta(models.Model):

    _PRODUCTOS = {
        Calculo.DIARIA:  TarifaDiaria,
        Calculo.SEMANAL: TarifaSemanal,
        Calculo.MENSUAL: TarifaMensual,
    }
    calculo_codigo = models.CharField(max_length=20, choices=Calculo.choices)

    # ---------- FACTORY METHOD ----------
    def calculo(self) -> CalculoPlan:
        return self._PRODUCTOS[self.calculo_codigo]()

Qué desacopló

La persistencia del algoritmo. La tabla guarda un texto; el código trabaja con objetos. Nadie más en el sistema necesita saber que ese texto existe.

Dónde se extiende

Un plan nuevo entra por un solo punto: una clase nueva, una entrada en _PRODUCTOS y una fila en plan_renta. Ni Reserva ni las vistas se tocan.

Un matiz que conviene decir antes de que lo pregunten: esta es la variante que el propio GoF llama factory method parametrizado — un solo método recibe un identificador y devuelve el producto, en lugar de una subclase por producto.

Se eligió así porque el discriminador ya existía como columna en la base (plan_renta.calculo_codigo): crear una subclase de PlanRenta por cada plan habría duplicado la tabla sin ganar nada. El mismo mecanismo se usa en EstadoReserva.crear(), que es la pieza que conecta una base relacional con un patrón de comportamiento — porque una tabla no puede guardar un objeto que sólo tiene comportamiento.
