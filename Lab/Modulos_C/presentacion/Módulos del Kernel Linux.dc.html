Concepto

Qué es un módulo del kernel

Un archivo .ko es código objeto ELF que el kernel enlaza en su propio espacio de direcciones mientras está en ejecución — sin reiniciar y sin recompilar el kernel.

01 Kernel pequeño Solo se carga en memoria lo que la máquina realmente usa.
02 Ciclo corto Compilar, cargar, probar y descargar en segundos.
03 Hardware nuevo Un driver de tercero se instala sin tocar el kernel base.
Arquitectura

Monolítico, pero modular

Monolítico

Drivers, sistemas de archivos y red comparten un mismo espacio de direcciones privilegiado. Las llamadas entre subsistemas son llamadas de función directas: rápidas, sin coste de mensajería.

Modular

Ese mismo espacio se puede extender en caliente. Un módulo no es un proceso aislado: es parte del kernel desde el instante en que se carga.

Consecuencia práctica: un puntero nulo en tu módulo no mata un proceso — provoca un kernel oops o un pánico de todo el sistema.

I

Gestión de módulos

Ciclo de vida, herramientas y rutas del sistema.

Ciclo de vida

De archivo en disco a código activo

.ko en disco Compilado kbuild produce el objeto con su tabla de símbolos y su vermagic.
insmod / modprobe Cargado El kernel resuelve símbolos, valida la firma y ejecuta module_init.
refcount > 0 En uso Mientras alguien lo referencie, el kernel rechaza descargarlo.
rmmod Descargado Se ejecuta module_exit: liberar todo lo reservado.

Regla de oro: exit deshace init en orden inverso. Cualquier recurso que no liberes se queda ocupado hasta el próximo reinicio.

Herramientas

El conjunto de kmod

lsmod
Lista los módulos cargados, su tamaño y quién los usa. Lee /proc/modules.
modinfo
Inspecciona un .ko sin cargarlo: autor, licencia, parámetros, vermagic, firma.
insmod
Carga un archivo por ruta exacta. No resuelve dependencias: falla si falta un símbolo.
modprobe
Carga por nombre desde /lib/modules/$(uname -r) y arrastra sus dependencias. -r descarga en cascada.
depmod
Reconstruye modules.dep y los mapas de alias. Obligatorio tras instalar un módulo nuevo.
rmmod
Descarga un único módulo. Falla si su contador de referencias no es cero.
Sistema de archivos

Dónde vive cada cosa

/lib/modules/$(uname -r)/kernel/     módulos del kernel de la distro
/lib/modules/$(uname -r)/extra/      módulos externos instalados
/lib/modules/$(uname -r)/build/      headers + kbuild (symlink)
/lib/modules/$(uname -r)/modules.dep grafo de dependencias (depmod)
/etc/modules-load.d/*.conf           módulos a cargar en el arranque
/etc/modprobe.d/*.conf               opciones, alias y blacklist
/proc/modules                        estado en vivo (lo que lee lsmod)
/sys/module/<nombre>/parameters/     parámetros legibles y escribibles
Pop!_OS · preparar el entorno sudo apt install build-essential linux-headers-$(uname -r) dkms
II

Escribir un módulo

Código mínimo, compilación con kbuild y parámetros.

hello.c

Anatomía del módulo mínimo

#include <linux/module.h>
#include <linux/init.h>

static int __init hello_init(void)
{
        pr_info("hello: cargado\n");
        return 0;      /* 0 = éxito */
}

static void __exit hello_exit(void)
{
        pr_info("hello: descargado\n");
}

module_init(hello_init);
module_exit(hello_exit);
MODULE_LICENSE("GPL");
__init Marca la función como desechable: su memoria se libera al terminar la carga.
return < 0 Devolver un errno negativo aborta la carga; el módulo no queda residente.
pr_info Envoltorio de printk(KERN_INFO …). No existe printf aquí.
MODULE_LICENSE Sin una licencia GPL compatible el kernel marca taint y te niega símbolos GPL-only.
Makefile

Compilar con kbuild

obj-m += hello.o

KDIR := /lib/modules/$(shell uname -r)/build
PWD  := $(shell pwd)

all:
	$(MAKE) -C $(KDIR) M=$(PWD) modules

clean:
	$(MAKE) -C $(KDIR) M=$(PWD) clean

install:
	$(MAKE) -C $(KDIR) M=$(PWD) modules_install
	depmod -a

obj-m declara qué objetos se construyen como módulo. Para un módulo de varios archivos fuente se usa en cambio mimodulo-objs.

obj-m          += mimodulo.o
mimodulo-objs  := core.o sysfs.o

Las tabulaciones de las recetas son obligatorias. M= le dice al árbol del kernel dónde está tu código fuera de él.

Flujo de trabajo

Compilar, cargar, observar, descargar

$ make                          # produce hello.ko
$ modinfo hello.ko              # licencia, vermagic, parámetros
$ sudo insmod ./hello.ko        # cargar por ruta
$ lsmod | grep hello            # confirmar que está residente
$ sudo dmesg -tH | tail -5      # leer los pr_info
$ sudo rmmod hello              # descargar
$ sudo dmesg -tH | tail -2      # confirmar el exit
Invalid module format El vermagic del módulo no coincide con el kernel en ejecución. Recompila contra los headers correctos.
Operation not permitted Secure Boot activo y módulo sin firmar: hay que firmarlo o deshabilitar la validación.
Parámetros

Configurar el módulo desde fuera

static int veces = 1;
static char *saludo = "hola";
static int lista[4];
static int lista_n;

module_param(veces, int, 0644);
MODULE_PARM_DESC(veces, "Repeticiones");

module_param(saludo, charp, 0644);
MODULE_PARM_DESC(saludo, "Texto a imprimir");

module_param_array(lista, int, &lista_n, 0644);
MODULE_PARM_DESC(lista, "Hasta 4 enteros");
En tiempo de carga 
sudo insmod hello.ko veces=3 \
     saludo="hey" lista=1,2,3
En caliente, vía sysfs 
cat /sys/module/hello/parameters/veces
echo 5 | sudo tee \
  /sys/module/hello/parameters/veces

El tercer argumento son los permisos del archivo en sysfs. 0 significa que el parámetro no aparece ahí.

Metadatos

Macros MODULE_* y licencias

MODULE_LICENSE("GPL")
Compatible con GPL: acceso completo a los símbolos exportados con EXPORT_SYMBOL_GPL.
MODULE_LICENSE("Proprietary")
El kernel queda marcado como tainted; los reportes de fallo pierden soporte upstream.
MODULE_ALIAS("…")
Nombre alternativo para que modprobe encuentre el módulo por petición del sistema.
MODULE_DEVICE_TABLE(…)
Publica los IDs de hardware soportados: es lo que permite la carga automática por udev.
MODULE_SOFTDEP("pre: x")
Dependencia blanda: sugiere a modprobe cargar otro módulo antes o después.

Drivers y depuración

Character devices, interfaces virtuales y lectura de fallos.

Character device · 1 de 2

Registrar el dispositivo

static dev_t          dev_num;
static struct cdev    mi_cdev;
static struct class  *mi_clase;

static int __init drv_init(void)
{
        alloc_chrdev_region(&dev_num, 0, 1, "midev");

        cdev_init(&mi_cdev, &mi_fops);
        mi_cdev.owner = THIS_MODULE;
        cdev_add(&mi_cdev, dev_num, 1);

        mi_clase = class_create("midev");   /* 6.4+ */
        device_create(mi_clase, NULL, dev_num,
                      NULL, "midev");
        return 0;
}

El resultado es /dev/midev, creado por udev a partir de la clase.

Salida ordenada En exit: device_destroy → class_destroy → cdev_del → unregister_chrdev_region.

Desde el kernel 6.4 class_create() recibe solo el nombre; el argumento THIS_MODULE desapareció.

El listado omite el manejo de errores; la versión completa está en el documento de referencia.

Character device · 2 de 2

La tabla file_operations

static char buf[256];

static ssize_t mi_read(struct file *f, char __user *u,
                       size_t len, loff_t *off)
{
        return simple_read_from_buffer(u, len, off,
                                       buf, strlen(buf));
}

static ssize_t mi_write(struct file *f,
                        const char __user *u,
                        size_t len, loff_t *off)
{
        if (len >= sizeof(buf))
                return -EINVAL;
        if (copy_from_user(buf, u, len))
                return -EFAULT;
        buf[len] = '\0';
        return len;
}
static const struct
file_operations mi_fops = {
        .owner = THIS_MODULE,
        .read  = mi_read,
        .write = mi_write,
};
__user Punteros que no puedes desreferenciar: siempre vía copy_to_user / copy_from_user.
.owner Sube el refcount mientras haya un descriptor abierto: evita descargar el módulo en uso.
Interfaces virtuales

Exponer estado por /proc y /sys

static int mi_show(struct seq_file *m, void *v)
{
        seq_printf(m, "contador=%d\n", contador);
        return 0;
}

static int mi_open(struct inode *i, struct file *f)
{
        return single_open(f, mi_show, NULL);
}

static const struct proc_ops mi_pops = {
        .proc_open    = mi_open,
        .proc_read    = seq_read,
        .proc_release = single_release,
};
sysfs · un valor por archivo 
static ssize_t contador_show(struct device *d,
        struct device_attribute *a, char *b)
{
        return sysfs_emit(b, "%d\n", contador);
}

static ssize_t contador_store(struct device *d,
        struct device_attribute *a,
        const char *b, size_t n)
{
        int ret = kstrtoint(b, 10, &contador);
        return ret ? ret : n;
}

static DEVICE_ATTR_RW(contador);

Se registra con device_create_file. Regla de sysfs: un archivo, un valor.

Depuración

Leer lo que dice el kernel

$ sudo dmesg -wH                      # seguir el log en vivo
$ sudo dmesg --level=err,warn         # solo errores y avisos
$ journalctl -k -b 0                  # log del kernel del arranque actual
$ sudo cat /proc/kmsg                 # búfer crudo

# encender los pr_debug de un módulo, sin recompilar
$ sudo mount -t debugfs none /sys/kernel/debug   # si no está montado
$ echo 'module hello +p' | sudo tee \
    /sys/kernel/debug/dynamic_debug/control
Niveles pr_emerg, pr_alert, pr_crit, pr_err, pr_warn, pr_notice, pr_info, pr_debug.
Oops Lee el call trace y resuelve la dirección con addr2line o decode_stacktrace.sh.
Aislar Prueba en una VM o con QEMU: un pánico de kernel se lleva la sesión entera.
IV

Distribución y seguridad

Firma, Secure Boot, DKMS y superficie de ataque.

Firma

Módulos firmados y Secure Boot

# 1. generar el par de claves (una vez)
openssl req -new -x509 -newkey rsa:2048 -nodes -days 3650 \
  -outform DER -keyout MOK.priv -out MOK.der \
  -subj "/CN=Modulos locales/"

# 2. registrar la clave en el firmware
sudo mokutil --import MOK.der    # pide una contraseña
sudo reboot                      # confirmar en MokManager

# 3. firmar el módulo tras cada compilación
sudo /usr/src/linux-headers-$(uname -r)/scripts/sign-file \
  sha256 MOK.priv MOK.der hello.ko

modinfo hello.ko | grep -E 'sig_id|signer'
mokutil --sb-state Comprueba si Secure Boot está habilitado antes de perseguir otros errores.
DKMS + MOK DKMS puede firmar automáticamente en cada reconstrucción vía /etc/dkms/framework.conf.
Guarda MOK.priv con permisos 600 y fuera de cualquier repositorio: firma código que corre como kernel.
Distribución

DKMS: sobrevivir a las actualizaciones

dkms.conf 
PACKAGE_NAME="hello"
PACKAGE_VERSION="1.0"
BUILT_MODULE_NAME[0]="hello"
DEST_MODULE_LOCATION[0]="/extra"
AUTOINSTALL="yes"
Instalación 
sudo cp -r . /usr/src/hello-1.0
sudo dkms add    -m hello -v 1.0
sudo dkms build  -m hello -v 1.0
sudo dkms install -m hello -v 1.0
dkms status
sudo modprobe hello

Con AUTOINSTALL="yes", cada nuevo kernel que instale Pop!_OS dispara la recompilación del módulo. Sin DKMS, el módulo desaparece silenciosamente tras la siguiente actualización.

Seguridad

Reducir la superficie de ataque

module.sig_enforce=1 Rechaza todo módulo sin firma válida, incluso sin Secure Boot.
kernel.modules_disabled=1 Congela la carga de módulos hasta el próximo reinicio. Es irreversible en caliente.
blacklist / install … /bin/false En /etc/modprobe.d/: impide la carga automática de módulos no deseados.
lockdown=integrity Bloquea las vías que permitirían a root modificar el kernel en ejecución.

En el código: validar toda entrada de usuario, comprobar límites antes de copiar, no confiar en strlen sobre datos externos y usar capable() para las operaciones privilegiadas.

Lista de verificación

Errores que se repiten

01Recursos reservados en init que exit no libera.
02No revisar el valor de retorno de cada registro.
03Desreferenciar punteros __user directamente.
04Buffers grandes en la pila: solo hay 8–16 KB.
05Dormir dentro de un spinlock o de un contexto atómico.
06Olvidar depmod -a tras modules_install.
07Compilar contra headers de otro kernel (vermagic).
08Probar en la máquina de trabajo en lugar de una VM.
